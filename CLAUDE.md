## Script layout (in order)

1. `LIST_ROWS` (the named lists, `@place` and so on), `CARD_ROWS` (the original cards, fixed in Phase 1), `PHONEME_ROWS` and `ADDED_ROWS` make `DEFAULT_SOURCE`. Cards refer to lists as `[@name]`; the `PLACES`, `MANNER`… constants are just those references. Card ids hold the row index, so **add new built-in cards at the end** of `ADDED_ROWS`. Before changing any built-in card, add `sourceFingerprint(DEFAULT_SOURCE)` of the current list to `LEGACY_DEFAULTS` so saved copies upgrade, and map any renamed card's old id in `RENAMED_IDS`. New cards are shuffled into an existing pile via `pc.known`.
   Then the phoneme section: `PHOIBLE_DATA` (generated, don't hand-edit), `describePhoneme(sym)` which reads features from the IPA symbol, tags and bands, and `poolFor` / `dealHand` for `[ipa:…]` pools.
2. `catInfo` / `suitFor`: corner rank (`/C/`, `[C]`, `/V/`, `[V]`, `/X/`, `ˈσ`, `σ`) and suit colour per category.
3. Parser: `compile(tpl, lists)` turns rule text into `parts` (text and slot pieces, each with `sp` for a space before it, and a `cond`) and `slots` (`kind`: number, pick, choice or pool, plus `sides`, `options`, `mult`, `offset`, `cond`; picks and choices also carry `list`, the named list they came from, and `types`, the `{type}` marks per option or null). `parseOptions` reads `a/b {type}/c`; `FEATURE_TYPES` lists the known types. `parseLibrary(src)` reads `@name` list rows first (so order doesn't matter), then cards, and returns `{ cards, problems, lists }`. It reads an optional last column of `key=value` tags into `card.tags`; `KNOWN_TAGS` (family, needs, effect, counts, feature, modifier) and `TAG_VALUES` (allowed `effect`, `counts` and `modifier` values) drive `card.tagIssues`, which the editor preview shows; `needs` values are checked against the whole card list at the end of `parseLibrary`, and `shapeWarnings` flags tags that don't fit the card's dice.
4. Rendering: `pieces` → `ruleHTML` (card in play), `ruleText` (plain text), `ruleHTMLDone` (deck), `rollSummary`, and `rolledFacts` (structured results stored as `entry.rolled`).
5. Language profile (still before the Dice marker, so the check script runs it): `cardWrites(tags, facts, src)` turns tags plus `slotFact`s into writes, `phonemeWrites` does the same for a mandated phoneme, `buildProfile` folds writes into per-key bounds (`need`, `max`) and totals, and `profileClashes` lists clashes, each with sides `a` (what needs) and `b` (what limits). Keys look like `place:velar`, `foot type:iambic` or a bare feature like `quantity`; `LIST_AREA` maps list names to areas (two lists can share one: `@airstream` writes to `special`, `@obstruent` to `manner`). `IMPLIES` says what including a key commits the language to (`{key}`, `{key, none}` to rule it out, `{total, min}`; `area:*` matches a whole area), and `impliesFor` reads it. `effect=gap` writes `cell:<voicing place manner>` or `cell:<height backness> vowel` with `max: 0`; plain mandated phonemes fill cells through `cellOf`, and `knownCells` (every cell the PHOIBLE table fills) catches gaps no language has. `counts=` may name several totals, matched to the card's number slots in order (`countNames`). `profileBase(deck)` is the deck's profile; `newClash`, `canFinish` (depth-first over the remaining slots), `slotChoices` (open and crossed-out values with reasons) and `blockReason` (pile filter; pass the deck and `cardFor` so modifiers can check for a target) test a candidate against it. `COUNTS`, the `counts=` vocabulary, sits in the parser section.
   Then changing kept cards (Re-roll and Flip tokens; `card.modifier` is the power-up kind: reroll, flip, choose, discard or cleanse, from `powerup=` or the older `modifier=`): `valuesFromEntry` reads a kept entry's `rolled` back into values, `changedSlots` is a slot plus the `(If …)` slots that depend on it, `modTargets` lists kept entries a modifier can act on (each with `base`, the profile without that entry, and `slots`), and `changedEntry` builds the replacement entry.
   Then pile copies (`copies=N`; `copyIds(card)` gives `id`, `id#2`…, `baseIdOf(pid)` goes back; `gameOnly(card)` is true for curses, Discard and Cleanse) and curses (`card.curse` is the curse kind on a curse card): `curseFrom` turns a rolled curse card into an active curse `{ kind, name, left, factor? }`, `cursesFor(card, active)` says which active curses change a card, `cursedCard(card, curse)` builds the cursed copy (cached; it sets `card.cursedBy`, rewrites wording with `EXACT_WORDING`, sets `mult` or `longOdds`), `entryCard(entry, cardFor)` rebuilds a kept entry's cursed card from `entry.curse`, and `optionFreq` gives a list option's PHOIBLE frequency for Long odds.
6. `Die` class: 2D throw physics in the tray, flick or tap, `prefers-reduced-motion` support. Picks rolled above the list length are re-rolled in `onSlotResult`.
7. App state (`state.pile`, `state.aside` and `state.used` hold pile ids, with copies; `state.used`: power-up and curse cards taken until the next reshuffle; `state.tokens`, `state.curses`, `state.game`), the pile filter (`refreshProfile` rebuilds `state.profile`, then `syncPile` moves blocked cards to `state.aside` with reasons in `state.asideWhy`; `blockFor` judges each card as `asDrawn`, cursed by the active curses), pile, card in play (`advance` computes `c.allowed` per slot and fills one-value slots with `forced`; `liveSlot` turns crossed-out values into a smaller die with `map` or `faces`), tray, deck, saving (`connectStore`), profile panel (`renderProfile`), editor, wiring, boot. The card in play carries `pid` (the pile id it was drawn as), `powerup` for a power-up card, and `card.cursedBy` when a curse changed it. A Re-roll or Flip token changing a kept card sets `state.current.mod` (`step`: target, slot or change; `tokenId`, `entryId`, `changed`) and `c.base`, the profile it's checked against (`baseFor`). "Power-ups and curses in play" holds `tokenUse` (can a token be spent now, and why not), `useToken`, `rerollInPlay`, `cleanse`, the change steps, `takeToken` (with the cap), `takeCurse`, `tickCurses` (counters, run on keep), `setGame` and `renderTokens`. `setTrayChoose` and `choose` handle Free pick; `onSlotResult` handles Long odds' second roll (`c.lo`). Boot moves renamed ids, turns `pc.free` into tokens, and drops saved in-play rolls that no longer fit the card (`valuesFit`).

## Saving

- With `db` available and a user id, the deck is stored in `data/users/<id>/deck/<entryId>` and a custom card list in `data/users/<id>/prefs/library`. Otherwise it falls back to `localStorage` keys `pc.deck`, `pc.source`, `pc.pile`, `pc.inplay` (with any dealt phoneme hands), `pc.known`, `pc.aside`, `pc.used`, `pc.sound`, and the game state `pc.game`, `pc.tokens` and `pc.curses` (browser only, like the pile, even with `db`). `pc.inplay` holds the card's `pid`, its `curse`, `powerup`, and a token's change as `mod`. Kept phoneme cards carry `phonemes: [symbols]` on the deck entry. Every entry kept since Phase 2 also carries `rolled`: one item per slot, `{ kind, value, list?, type? }` or `{ skipped: true }`. Older entries have only `text` and `rolls`. An entry changed by a Re-roll or Flip token keeps its id and carries `changes: [{ by, was, at }]`. An entry kept under a curse carries `curse: [{ kind, name, factor? }]`, and stays cursed for good.
- The language profile is **derived from the deck**, never stored separately. Entries kept since Phase 3 also carry `tags`; the profile prefers the library card's tags when a card with the same id and name exists, so tag fixes apply to old entries. Rolled values may carry `roll` and `of` (the face on a smaller die) or `forced` (set without a roll, with the reason).

## Checking changes

- Run `node scripts/check-cards.js` after any parser, profile or card-list change. Its last line must report 0 clashes reaching a deck and 0 cards stuck. The random games play the game layer: tokens with the cap, Re-roll and Flip on kept cards, Cleanse, and curses changing the cards drawn. It also prints every ceiling card's Exact count wording and the PHOIBLE frequencies Long odds uses. It needs the `'use strict';` and `/* ---------- Dice` markers to stay in the script.
- To rebuild the phoneme table: download `https://raw.githubusercontent.com/phoible/dev/v2.0/data/phoible.csv` (26 MB, keep it out of the repo) and run `node scripts/build-phonemes.js path/to/phoible.csv`. It prints the segments it couldn't read.
- For UI changes, one headless Playwright run is enough: draw with `d`, roll with `r`, keep with `k` (it also takes tokens and curses), tap `#tokens .tok` buttons, and watch for page errors. Wrap the file in a doctype skeleton and load it from `file://` so `localStorage` works.

## Conventions

- User-facing copy is plain and direct. Avoid em-dashes in UI text.
- Card data belongs to the user. Flag suspected mistakes in their cards (like `[10]` or the typo "Nucelus"); don't silently change them.
